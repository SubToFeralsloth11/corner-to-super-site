# Corner to Super: build log site

A one-page site describing what has been built for *Corner to Super*, a first-person supermarket
game in Godot 4.7: the features, a dated timeline, how it was built, the numbers, the economy,
credits and current status.

Live: https://subtoferalsloth11.github.io/corner-to-super-site/

The game's repository is private. This repo holds only the site. The only images are asset
contact sheets copied from the game repo, not in-game screenshots.

## Files

| File | What it is |
|---|---|
| `index.html` | The page. Static text for the features, the build process, the credits and the status |
| `style.css` | Styles: light and dark via `prefers-color-scheme`, responsive |
| `app.js` | Small vanilla script that reads `data.json` and draws the timeline, stat cards, charts, economy tables and deferred checks (inline SVG, no libraries) |
| `data.json` | Generated by `update.py`. Do not edit by hand |
| `manual.json` | Hand-written timeline events and test runs that the game repo doesn't record (taken from the build session and the agents' reports) |
| `update.py` | Regenerates `data.json` |
| `img/` | Asset contact sheets (fixtures, products, humans) resized to 1600 px |
| `live.html`, `live.js`, `live.css` | The live page for the critique-and-fix loop: current status, agents, findings per round, the full activity log, test runs, the latest game commits and machine load. Polls `live.json` every 30 s from the raw GitHub URL so it updates without waiting for a Pages build |
| `live.json` | Written by `live.py`. Do not edit by hand |
| `live.py` | CLI the agent calls for every step (`status`, `round`, `finding`, `fix`, `test`, `agent`, `log`); `--push` or `push` also refreshes `data.json`, samples the machine and the game repo, commits and pushes |

There is no build step, no CDN and no tracker. GitHub Pages serves `main` at `/`.

## Refreshing the data

When more work lands in the game repo (M9, review additions batch B, later review rounds):

```sh
python3 update.py                                  # reads ~/Code/corner-to-super
python3 update.py --game /path/to/corner-to-super  # or point it elsewhere
git add data.json && git commit -m "Refresh site data" && git push
```

`update.py` only reads the game repo (`git log main`, `docs/PROGRESS.md`, `docs/ECONOMY.md` and
`data/*.json`). It needs Python 3.9+ and nothing else. It collects:

- **Commits**: every commit on `main` with its date, plus commits per hour for the activity chart.
- **Test runs**: every full-suite `N passed, M failed` line that `PROGRESS.md` still reports,
  dated by the commit that first added it, merged with the runs listed in `manual.json`.
- **Timeline**: the events in `manual.json`, plus an event for every `## ` section of
  `PROGRESS.md` that no manual event covers. A new milestone note shows up on its own; give it
  proper text by adding an event with a matching `"progress"` title to `manual.json`.
- **Deferred checks**: each PROGRESS section's `**Deferred...**` list (windowed screenshots,
  frame-rate and listening checks that haven't been run yet).
- **Economy**: licences, expansions and stockroom stages from `data/*.json`, and the pacing table
  from `ECONOMY.md`, so M9's tuned numbers appear after a refresh.
- **Counts**: commits, products, licences, fixtures, levels, test files, GDScript files and lines,
  `.glb` models, sounds and music tracks; also branches not yet merged into `main`.

Things that change by hand: the feature text and the status section in `index.html`, and the
"in progress" entries in `manual.json` (remove them once M9 and batch B land).

To preview locally: `python3 -m http.server` in this folder, then open http://localhost:8000/
(opening `index.html` as a file blocks the `data.json` fetch).
